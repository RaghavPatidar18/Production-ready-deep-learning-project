                             KEY INSIGHTS
═══════════════════════════════════════════════════════════════════════════════

🔑 WHY IT WORKS:

1. DETERMINISTIC ORDERING
   └─ Python's sorted() always produces same alphabetical order
   └─ "freshripe" will ALWAYS be index 0 across all phases

2. CONSISTENT PREPROCESSING
   └─ All images rescaled by dividing by 255.0
   └─ All images resized to 224×224

3. SAVED MAPPING
   └─ Training saves class_indices.json
   └─ Prediction loads this file for accurate mapping

4. MODEL OUTPUT STRUCTURE
   └─ Model ALWAYS outputs 6 probabilities (one per class)
   └─ Index position corresponds to class index


⚠️  WHAT COULD BREAK IT:

❌ Changing folder names after training
   └─ "ripe" → "banana_ripe" changes alphabetical order!

❌ Different preprocessing
   └─ Training uses /255, prediction uses /1 → wrong results

❌ Missing class_indices.json
   └─ Falls back to hardcoded mapping (works but not ideal)

❌ Different number of classes
   └─ Model expects 6 outputs, not 5 or 7


✅ BEST PRACTICES IMPLEMENTED:

1. Save class indices during training
2. Load class indices during prediction
3. Print mappings for verification
4. Consistent preprocessing everywhere
5. Clear documentation and logging
